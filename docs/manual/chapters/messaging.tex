\section{Messaging}
\label{sec:Messaging}

Kafka is used as the ordered fan-out path for accepted Archimesh operation
batches, lock events and presence events.

\subsection{Topic layout}

Three topic kinds exist per model:

\begin{longtable}{p{46mm}p{54mm}p{54mm}}
\toprule
Topic pattern & Content & Partitioning \\
\midrule
\code{archimesh.model.<modelId>.ops} & Committed op batches &
  Exactly 1 partition (required) \\
\code{archimesh.model.<modelId>.locks} & Lock acquire/release/expire &
  1 partition \\
\code{archimesh.model.<modelId>.presence} & Cursor/selection broadcasts &
  1 partition (or keyed by sessionId) \\
\bottomrule
\end{longtable}

The topic prefix is configurable via \code{KAFKA\_TOPIC\_PREFIX} (default
\code{archimesh.model}).

\subsection{Single-partition requirement}

Each model's ops topic \textbf{must} have exactly one partition. This is a
hard constraint, not a recommendation. Multiple partitions would allow
operations to be consumed in different orders by different clients, breaking
the total order guarantee that the deterministic merge semantics depend on.

Topic keys:

\begin{itemize}
\item ops: constant key = \code{<modelId>}
\item locks: constant key = \code{<modelId>}
\item presence: key = \code{<sessionId>} (or \code{<userId>})
\end{itemize}

\subsection{Producer}

The \code{KafkaPublisherImpl} uses a \texttt{KafkaProducer<String,{}String>}
with:

\begin{itemize}
\item \code{acks=all} --- wait for all in-sync replicas
\item \code{retries=3}
\item \code{delivery.timeout.ms=120000}
\item String serializers for both key and value
\end{itemize}

Publishing is asynchronous. The \code{publishOps} method returns a
\code{CompletableFuture<Void>} that completes when the broker acknowledges
the send. Committed operation batches are published by
\code{CommitDeliveryService}. It reads pending Neo4j payloads in model
revision order, waits for broker acknowledgment, then marks publication complete.
Failed or interrupted sends leave the durable intent pending for retry.

Pending model discovery is separate from payload decoding. A cursor rotates
through sorted pending model IDs, scanning at most 100 IDs per pass. A bounded
pool handles independent models concurrently, with at most one queued or
running worker per model. Each visit publishes a limited prefix in revision
order, awaiting broker acknowledgment and the Neo4j flag write before its
successor. A large backlog in one model cannot fill the discovery window for
every other model.

\manualfigure[\linewidth]{commit-delivery}{Durable acceptance and asynchronous operation fan-out.}{commit-delivery}

The two branches in Figure~\ref{fig:commit-delivery} have separate durability
boundaries. Acceptance confirms the Neo4j commit to the submitting session;
broadcast reaches every subscriber through the Kafka consumer. Either can
arrive first. A failed model transaction receives no acceptance.

\subsection{Consumer}

The \code{KafkaConsumerImpl} runs a single-threaded consume loop with:

\begin{itemize}
\item Group id: \code{archimesh-server} (configurable via
  \code{KAFKA\_CONSUMER\_GROUP\_ID})
\item Auto offset reset: \code{earliest}
\item Topic subscription via regex pattern matching all
  \code{<prefix>.<modelId>.<kind>} topics
\item 500 ms poll timeout
\end{itemize}

On receiving a record, the consumer parses the topic name to extract the
model id and kind, then broadcasts the payload to all sessions registered
for that model:

\begin{description}
\item[ops] Broadcasts \code{OpsBroadcast} to all sessions for the model.
  The submitter reconciles its own echo against the optimistic local state.
\item[locks] Broadcasts \code{LockEvent}.
\item[presence] Broadcasts \code{PresenceBroadcast}.
\end{description}

The consumer is resilient to Kafka unavailability: on connection failure it
sleeps and retries. While publication or consumption is unavailable, other
clients can lag behind the accepted state. Durable publication retry and a
subsequent complete delta or snapshot checkout restore synchronization.

\subsection{Retention}

\begin{description}
\item[ops] Retain enough for expected consumer outages and lag. Neo4j
  checkpoints plus the operation tail provide the implemented rebuild source;
  Kafka is the fan-out path, not the model backup.
\item[locks] Short retention (minutes). Lock state is ephemeral.
\item[presence] Very short retention (minutes). Presence is transient.
\end{description}

\subsection{Publication failure and duplicate delivery}

If Kafka accepts a batch but the server stops before Neo4j records the
publication flag, restart can publish it again. Delivery is at least once;
clients tolerate duplicate committed ranges and reconcile accepted echoes.
Retrying a submitted batch consults the persisted acceptance receipt and
returns the original revision range without committing again.

Publication payloads are retained until acknowledged. Pruning never crosses
the first unpublished or unclassified legacy batch, even when a newer
checkpoint covers its state. Lock and presence events use direct Kafka
publication and do not share the durable operation outbox.

A publication failure, invalid or missing payload, or acknowledgment-write
failure stops that model's visit and defers retries for at least one second.
Its batch and successors remain pending while other model workers continue.
Stored payload identity, range and operation count must match the receipt.
A slow broker send retains its model slot until it settles; later batches
cannot overtake it. If every worker slot is occupied, other models wait.
Lease renewal runs separately from the model workers, and shutdown interrupts
pending waits without acknowledging them. Cursor and cooldown state are
process-local; restart recovers work from the durable queue.

Delivery limits are configured separately from Kafka:

\begin{description}
\item[\code{app.delivery.concurrent-models}]
  \code{ARCHIMESH\_DELIVERY\_CONCURRENT\_MODELS}, default 4.
\item[\code{app.delivery.batches-per-model}]
  \code{ARCHIMESH\_DELIVERY\_BATCHES\_PER\_MODEL}, default 25.
\end{description}

Both must be positive. Submit bursts coalesce immediate scan requests; the
periodic scan also runs once per second. Apply \filepath{neo4j/schema.cypher}
to install the \code{commit\_delivery} queue index on
\code{(published, modelId, revisionFrom)}. Model-specific delivery warnings
identify blocked models; broker-wide and database-wide outages can still
affect all workers.

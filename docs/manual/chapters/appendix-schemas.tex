\section{Wire Protocol and Schema Reference}
\label{sec:AppendixSchemas}

This appendix documents the JSON schemas that define the Archimesh wire
protocol contract. The authoritative schema files live in
\filepath{schemas/}.

\subsection{Schema files}

\begin{longtable}{p{42mm}p{112mm}}
\toprule
File & Purpose \\
\midrule
\code{common.json} & Shared type definitions: \code{ModelId},
  \code{UserId}, \code{SessionId}, \code{EntityId},
  \code{RFC3339}, \code{Causal}, \code{Actor},
  \code{RevisionRange}, \code{JsonObject}. \\
\code{ops.json} & Operation type definitions for all supported op types:
  create, update, delete for elements, relationships, views, view objects,
  connections, folders; property and membership operations; plus strict
  notation JSON objects for view objects and connections. \\
\code{op-batch.json} & Op batch envelope: \code{SubmitOps} with
  \code{baseRevision}, \code{opBatchId}, \code{actor} and
  \code{ops} array. \\
\code{lock-event.json} & Lock event payload: action (acquired, released,
  expired), actor, targets, timestamp. \\
\code{presence.json} & Presence payload: modelId, userId, sessionId,
  viewId, selection array, cursor object. \\
\code{notation-contract.md} & Human-readable contract describing the
  notation field boundaries and parity requirements. \\
\bottomrule
\end{longtable}

\subsection{Message flow summary}

\begin{longtable}{p{30mm}p{30mm}p{94mm}}
\toprule
Direction & Type & Description \\
\midrule
Client $\to$ Server & \code{Join} & Request checkout. Optional
  \code{lastSeenRevision} and \code{ref}. \\
Client $\to$ Server & \code{SubmitOps} & Submit one op batch.
  \code{baseRevision}, \code{opBatchId}, \code{ops}. \\
Client $\to$ Server & \code{AcquireLock} & Acquire notation lock on
  targets. \code{ttlMs}. \\
Client $\to$ Server & \code{ReleaseLock} & Release notation lock on
  targets. \\
Client $\to$ Server & \code{Presence} & Broadcast cursor position and
  selection on a view. \\
\midrule
Server $\to$ Client & \code{CheckoutSnapshot} & Full materialized model
  state. \\
Server $\to$ Client & \code{CheckoutDelta} & Incremental ops since
  \code{lastSeenRevision}. \\
Server $\to$ Client & \code{OpsAccepted} & Batch commit confirmation with
  assigned revision range. \\
Server $\to$ Client & \code{OpsBroadcast} & Remote batch broadcast (Kafka
  fan-out through the consumer). \\
Server $\to$ Client & \code{LockEvent} & Lock state change notification. \\
Server $\to$ Client & \code{PresenceBroadcast} & Remote cursor/selection
  update. \\
Server $\to$ Client & \code{Error} & Rejection or failure with
  \code{code} and \code{message}. \\
\bottomrule
\end{longtable}

\subsection{Error codes}

\begin{longtable}{p{46mm}p{108mm}}
\toprule
Code & Meaning \\
\midrule
\code{REVISION\_AHEAD} & Client \code{baseRevision} exceeds server
  head. Client must rejoin. \\
\code{PRECONDITION\_FAILED} & Referenced entity does not exist, or
  notation contains unknown keys. \\
\code{LOCK\_CONFLICT} & Another client holds a conflicting notation lock. \\

\end{longtable}

\subsection{Export/import format}

Without a checkpoint the server emits a v1 package containing:

\begin{lstlisting}[caption={Export package structure}]
{
  "format": "archi-model-export-v1",
  "exportedAt": "<UTC timestamp>",
  "model": { "modelId": "...", "modelName": "...", "headRevision": 42 },
  "accessControl": { "configured": true, "adminUsers": [...], ... },
  "snapshot": { "format": "archimate-materialized-v1", ... },
  "opBatches": [ { "modelId": "...", "opBatchId": "...", ... } ],
  "tags": [ { "tagName": "...", "revision": 24, "snapshot": {...} } ]
}
\end{lstlisting}

The package format is documented in full in \filepath{server/EXPORT\_FORMAT.md}.

Checkpointed exports use \code{archi-model-export-v2}. They add
\code{checkpoint} (format, model ID, revision C, timestamp, checksum and raw
state) and \code{receipts} (batch IDs, original ranges and timestamps covering
1..C). Their \code{opBatches} contain exactly the tail C+1..HEAD, which can be
empty at C=HEAD. V1 remains supported. See Section~\ref{sec:Management} for
atomic v2 restore, target model rebinding and full-history archive requirements.
